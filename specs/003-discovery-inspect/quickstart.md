# Quickstart: bazel-git-lfs inspect (Stage 2 — Discovery)

Discover the remote HTTP dependencies a Bazel project needs. `inspect` runs in the current project, prints structured JSON, and persists the result to `.bazel_git_lfs/dependencies.json` for fast `list` reads.

## Prerequisites

- The tool from Stage 1 (`bazel-git-lfs` built and on PATH, or `node dist/index.js`)
- The project must be initialized: `bazel-git-lfs init`

## Initialize the project

```bash
cd <your-bazel-project>
bazel-git-lfs init
```

## Inspect the current project

```bash
bazel-git-lfs inspect
```

Prints valid JSON with every `http_archive`/`http_file` dependency found in `WORKSPACE`, `WORKSPACE.bazel`, `MODULE.bazel`, and any loaded `.bzl` files — name, all URLs, SHA256, strip prefix, source file — plus the snapshot path, warnings, scanned files, and the `bazel query` cross-check status. Nothing is downloaded or modified; the only write is the snapshot under `.bazel_git_lfs/dependencies.json` (atomic).

If the project is not initialized, `inspect` reports:

```json
{ "ok": false, "error": "Not a valid bazel_git_lfs project: <dir>. Run \"bazel-git-lfs init\" first." }
```

## What it handles

- Literal `http_archive`/`http_file` calls (single `url` or `urls` list)
- Dependencies declared in `.bzl` files that are `load()`ed from the entry files
- Multi-line calls and comments
- Dependencies generated by `for` loops over variable lists (names/URLs/SHA256s)
- Cross-checking against Bazel's native `query` when available (identifies actually-used external repos and dependency relationships; falls back to file inspection otherwise)
- Projects with no HTTP dependencies (reports an empty result, exit 0)

If a loop-generated declaration can't be fully resolved, a `load()` target is missing, or Bazel query is unavailable, it's reported in `warnings` rather than silently dropped.

## Errors

- Not initialized → `Not a valid bazel_git_lfs project: <dir>. Run "bazel-git-lfs init" first.` (JSON, exit 1)
- Unparsable/unreadable Bazel file → JSON error naming the file (exit 1)
- `.bazel_git_lfs` not writable → JSON error with a clear message (exit 1)
- Extra arguments or unknown options → usage error (exit 2)
