# Quickstart: bazel-git-lfs scan (Stage 2 — Discovery)

Discover the remote HTTP dependencies a Bazel project needs. This stage is read-only — nothing is downloaded or changed.

## Prerequisites

- The tool from Stage 1 (`bazel-git-lfs` built and on PATH, or `node dist/index.js`)
- The project must be initialized: `bazel-git-lfs init`

## Initialize the project

```bash
cd <your-bazel-project>
bazel-git-lfs init
```

## Scan a project

```bash
bazel-git-lfs scan            # scan the current directory
bazel-git-lfs scan ./graph_runtime   # scan a specific project
```

Lists every `http_archive`/`http_file` dependency found in `WORKSPACE`, `WORKSPACE.bazel`, and `MODULE.bazel`, with name, SHA256, source file, and primary URL. Nothing is downloaded or modified.

## Machine-readable output

```bash
bazel-git-lfs scan ./graph_runtime --json
```

Prints structured JSON with the full dependency set — useful for scripts and CI.

## What it handles

- Literal `http_archive`/`http_file` calls (single `url` or `urls` list)
- Dependencies declared in `.bzl` files that are `load()`ed from the entry files
- Multi-line calls and comments
- Dependencies generated by `for` loops over variable lists (names/URLs/SHA256s)
- Cross-checking against Bazel's native `query` when available (identifies actually-used external repos and dependency relationships; falls back to file scanning otherwise)
- Projects with no HTTP dependencies (reports an empty result, exit 0)

If a loop-generated declaration can't be fully resolved, a `load()` target is missing, or Bazel query is unavailable, it's reported in `warnings` rather than silently dropped.

## Errors

- Not initialized → run `bazel-git-lfs init` first.
- Missing/unreadable project dir or unparsable Bazel file → error on stderr, non-zero exit.
